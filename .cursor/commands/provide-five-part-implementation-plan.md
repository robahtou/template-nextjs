# Provide a Five-Part Implementation Plan

Plan `$ARGUMENTS` without editing files. Inspect the affected code and canonical guidance, then use exactly these sections:

1. **Problem and outcome** — Success, constraints, and non-goals.
2. **Current state** — File-referenced behavior, dependencies, and confirmed gaps.
3. **Design** — Chosen approach, ownership boundaries, and material trade-offs.
4. **Implementation steps** — Ordered file-level edits, removals, and documentation changes.
5. **Validation and risks** — Tests, repository checks, acceptance criteria, rollback concerns, and deferred work.

Separate verified facts from assumptions. Ask only questions whose answers would materially change the design.
