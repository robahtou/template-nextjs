# Provide an Implementation Plan

Plan the change in `$ARGUMENTS` without editing files.

1. Restate the outcome, constraints, and non-goals.
2. Inspect the affected implementation, tests, `README.md`, nearest `CONTEXT.md`, manifests, and configuration.
3. Explain current behavior with file references and distinguish evidence from assumptions.
4. Resolve material design choices; ask only questions that would change the plan.
5. Provide ordered, file-specific implementation steps, including removals and durable documentation updates.
6. Define focused tests, repository checks, runtime acceptance criteria, and expected results.
7. Close with risks, rollback considerations, and explicitly deferred work.

Keep the result concise, implementation-ready, and consistent with the project's greenfield stance.
