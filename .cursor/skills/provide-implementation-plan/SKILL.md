# Provide an Implementation Plan

Do not implement the change.

1. Restate the requested outcome and explicit non-goals.
2. Inspect `README.md`, the nearest `CONTEXT.md`, manifests, configuration, and affected code.
3. Describe the current behavior with file references; distinguish evidence from assumptions.
4. Resolve material design choices and call out any decision that still requires the user.
5. List ordered, file-specific implementation steps. Include removals and documentation updates where behavior or ownership changes.
6. Specify focused tests, repository checks, and runtime acceptance criteria.
7. End with risks, rollback considerations, and deferred work.

Keep the plan implementation-ready, concise, and consistent with the greenfield stance.
